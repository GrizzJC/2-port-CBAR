# Repository maintenance and handoff

Maintain one authoritative [inventory](../../inventory.csv), one [naming standard](../NAMING-AND-FILE-RULES.md) and useful system documentation. Do not add empty trackers that must be manually synchronized. Keep saved source-project references and meaningful test evidence when known.

Use the `main` branch for the maintained repository while preserving commit history. Keep source-file licensing and author credit. Do not place sensitive laboratory data or identifiable records into a public repository without proper authorization.

Source and software may be developed locally. A known unpublished significant change can be noted as Revision Pending, but GitHub only tracks committed files. Verify dependencies before renaming and do not equate imported files with approved installed equipment.

Repository transfer to a laboratory organization or another owner should be completed only when authorized, with permissions, source licensing and integrations verified. See [GitHub's transfer guidance](https://docs.github.com/en/repositories/creating-and-managing-repositories/transferring-a-repository).
